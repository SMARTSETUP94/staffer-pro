# Quote library rules

- Supplier catalogue imports stage rows in chunks, show a price-change summary, then deactivate (never delete) the supplier's previous rows; quote lines copy prices at insertion so catalogue updates never alter existing quotes.
- Material search ranks on derived search_norm/produit_norm columns built by materiaux_norm (× * x unified, letters split from digits) plus the admin-editable materiaux_synonymes table; short terms match whole words only and a trigram prefilter keeps queries under one second.
- MCP photo URLs are fetched server-side with a hostname allow-list re-checked on every redirect, no IP literals, a 10 MB streaming cap and signature-based type detection, so Claude never needs to inline large base64 files.
- ProGBat exports are built only from devis_progbat_donnees (client view + hours per line) by the pure progbat-export.ts; rounding gaps are absorbed in the Suivi/Pose/Dépose lump-sum line so the file total always equals Staffing HT. Transfer (numero_progbat: provisional S… after import, then definitive D-… after human finalisation, both through devis_enregistrer_transfert) and client sending (date_envoi) are distinct facts under the same frozen `transfere` status, keeping legacy sent quotes unchanged; MCP export/transfer tools accept conversation mode only.
- Client PDF and ProGBat share titreCourt/descriptifChapitre/detailObjet from pdf-client.ts and both refuse export when champsClientManquants is non-empty; displayed subtotals exclude non-included options so every page adds up to the totals.
- Company logos use immutable private entreprise-logo paths and browser PNG conversion; restrictive storage policy allows only admin insertion. Missing issuer/signatory metadata uses the pure pdf-avertissements helper and never blocks PDF generation.
- Price proposals live in materiaux_catalogue as inactive rows (proposition_statut) and become active only via admin materiau_proposition_valider; quote lines are never written, imports only deactivate imported rows, and the pure materiaux-propositions.ts mirrors the database checks.
- Supplier documents (materiaux_documents, private documents-fournisseurs bucket without storage policies) are uploaded and read only by server functions that compute the path, re-check owner/hash/real type/10 MB before submission and sign links from a document id; their lines enter the same proposition circuit, and a ponctuel price never replaces or updates a reference price.
- Quote image proposals (images-ia.ts pure rules, images-ia.server.ts core shared by app and MCP) read affair-box images and PDF-derived rows (affaire_documents.document_parent_id, server text/light-image extraction, browser page renders re-validated and stored by a server function); limit/cost are checked before the AI call and the server records devis_propositions_photos, so the browser never writes proposals or storage directly.
- Box images are copied into devis-photos only by server code (copierDocumentVersDevis / MCP write) that removes its own unreferenced copy with the service client if devis_photo_ajouter fails; users get no storage delete right.
- Note and comment edits (devis.note_mcp, commentaire texte) are written only through devis_texte_modifier / devis_note_fusionner and traced by database triggers into devis_textes_historique (author source from mcp_dispatch_actif), so editor, MCP and restores share one audit path; Claude submissions append after a human version instead of overwriting.
